# D-254 — Which kinds may the server and the engine name?

Topic: The planner's UIs.
State: Unanswered.
Context: `docs/units/names-declared-once.md` asks for a gate that fails
when the kernel, the server, the runner, or the engine names a kind
(D-244: its load op, its hash field, or its name as a string literal in
code). Counted on 2026-11-25, outside comments and tests: the server 147,
the engine 51, the runner 3, the kernel 0. Most of them name a feature
that is the kind itself: the server imports the feed and serves
`/network`, `/network/boundary`, `/streets` and `/walks`. It also
publishes picks (`/plans`), speaks the edit protocol (`/edits`), checks
writes against the `policy`, and keeps the `build` and the `manifest`.
The engine loads the network, the boundary and the feed by the ABI. The
kinds the kind table routes generically are named much less. Those are a
`post` route answered by a log's receive op, the `work_order` route, and
a pointer write checked by its module. The work order path now reads the
table. Only `stops` is still named, 9 times: a pick's export reads its
history (D-151), a pick reads it on its first date, and the feed's
differences go to the stops log (`import_events`).
Options:
- The gate covers the generically routed kinds (recommended). The
  plumbing names no kind with a `post` route, a `work_order`, or a
  pointer write. A kind the server imports, publishes, or serves on a
  route of its own (`write: server`, or a `route` write with no
  `post`) is the server's feature, and the server and the engine may
  name it. The three `stops` uses become named fields in the stops
  line (each difference a field, never a hook). Cost: about a day, and
  the server keeps its own features by name.
- The literal gate: the plumbing names no kind. Every server feature
  above moves behind fields in the kind table and generic handlers, and
  so does the engine's handling of the network, the boundary, and the
  feed. Cost: weeks, and most of the fields would be one kind's
  feature under another name.
- No kind gate. The capability gate and the generated op map stay.
  Cost: nothing fails when a generic kind's name creeps into the
  plumbing.
